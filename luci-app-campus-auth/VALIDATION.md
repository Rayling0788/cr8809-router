# 修复与实机测试记录

日期：2026-09-29。设备：CR8809，ImmortalWrt 23.05-SNAPSHOT。

## 审查发现与修复

- 旧页面缓存导致用户看不到入口。改用新的视图文件名，清理实际带后缀的 LuCI 菜单缓存，浏览器刷新后确认扫描按钮出现。
- LuCI RPC 的 `expect: { results: [] }` 已经提取数组，旧代码再次读取 `.results`，导致扫描结果始终为空。改为直接读取数组。
- 操作期间禁用扫描、选择和重复连接；后台增加互斥锁。
- 连接成功后同步页面表单的单路选择，避免随后保存覆盖刚选择的频段。
- 修正 WPA 版本识别、WPA2/WPA3 混合密码长度，设置 WPA3 所需的管理帧保护；保留企业认证不支持的提示。
- 写入前确认接口对应关系、拒绝覆盖尚未提交的无线设置；已有备份恢复逻辑保留。

## 实际执行的测试

- JavaScript 语法检查、路由器 shell 语法检查通过。
- 浏览器实际扫描：5 GHz 11 个热点、2.4 GHz 19 个热点，列表均正常显示。
- 选择 WPA2 热点时密码框启用；空密码连接被页面拦截。选择开放热点时密码框禁用。
- 后台拒绝空 SSID、无效频段、过短 WPA2 密码、过短 WPA2/WPA3 混合密码；配置无待提交更改。
- 浏览器点击连接原有 `原有5GHz校园热点` 后收到后台成功响应，无浏览器控制台错误。
- 实机确认 wwan2 已关联同一 SSID、获得 IPv4 地址；wan 仍在线，wwan3 停用，单路设置为 wwan2。
- 绑定 Wi-Fi 上行地址访问 HTTPS 返回 HTTP 200；ping 3/3 成功，丢包率 0%，平均约 22 ms。

## 测试范围与限制

本次真实连接测试使用现有开放校园热点。加密网络的识别、输入和拒绝逻辑已测试，但没有可用的其他热点密码，因此未实测 WPA2/WPA3 握手。错误密码导致无法关联时，页面的“设置已保存”不代表已联网，也不会自动回滚。企业认证、隐藏 SSID 尚不支持。



## 分频段页面更新与三路实测

- v3 将 2.4 GHz / 5 GHz 分成独立区域，显示启用标记、实际关联 SSID、保存的 SSID 和 IPv4，每 5 秒刷新。
- 按用户要求保留路数与单路频段选择，热点保存不再修改 `wifi_count`、`single_wifi` 或任何接口的 `disabled`。
- 三路临时启用后，mwan3 确认 wan、wwan2、wwan3 全在线；有线优先为 60% / 20% / 20%。测试后恢复用户原有单路 2.4 GHz 设置。
- 三路分别使用临时源地址路由规则固定到各自路由表，并用 `ip route get` 确认实际出口；每条 HTTPS 均返回 200，ping 均 3/3 成功。平均时延：有线 21.9 ms，5 GHz 50.0 ms，2.4 GHz 53.5 ms。临时规则已自动删除。
- 更正前一阶段测试方法：仅绑定源地址不能确保走对应 Wi-Fi，三路实测已加入明确的出口路由校验。
- 浏览器确认当前 2.4 GHz“启用、原有2.4GHz校园热点”，5 GHz“未启用、当前未连接”，保存热点仍显示 原有5GHz校园热点；两个列表独立扫描。
